1. Introduction

This assignment investigates movie ratings collected from five participants. Six recent popular movies were selected, and participants (5 of them) were asked to rate each movie they had seen using a 1–5 rating scale.

The achievements of this assignment are creating a database, three tables, populating the tables with constant values and then storing the data into database.

Subsequently, importing the database into R and analyse using it.

2. Questions to answer through this assignment

The assignment addresses the following questions:

1. Which movie received the highest average rating?

2. How many ratings did each movie receive?

3. How should missing ratings be handled?

4. How do individual participants differ in their average ratings?

5. How can the data be represented as a user-item matrix?

3. Database Design

The database contains three tables:

  • users (user_id, name)

  • movies(movie_id, title)

  • ratings (user_id, movie_id, rating)

The `ratings` table connects users and movies through foreign keys. The primary key of the ratings table consists of the combination of `user_id` and `movie_id`, ensuring that a participant cannot submit multiple ratings for the same movie.

5. Retrieve Data from SQL

movie_ratings <- dbGetQuery(
  con,
  "
  SELECT
      u.user_id,
      u.user_name,
      m.movie_id,
      m.title,
      m.release_year,
      r.rating
  FROM ratings AS r
  INNER JOIN users AS u
      ON r.user_id = u.user_id
  INNER JOIN movies AS m
      ON r.movie_id = m.movie_id
  ORDER BY u.user_id, m.movie_id
  "
)

7. Missing Data

Not every participant had seen every movie. Therefore, missing ratings

are represented by NULL in PostgreSQL and become NA in R.

These values are not treated as zero because zero is not part of the

1–5 rating scale.

13. Interpretation

The average-rating analysis identifies which movies were most highly rated by the participants. The number of ratings is also important because not every participant had seen every movie. Therefore, averages should be interpreted together with the number of observations contributing to each average. Missing ratings were not converted to zero. Instead, they were treated as missing observations because a participant who had not seen a movie could not reasonably provide a rating.

14. Limitations

This dataset has several limitations.

First, the sample size is small because the assignment requires only five participants. Therefore, the results cannot be eneralized to the broader population.

Second, participants may have different movie preferences and levels of familiarity with the selected movies.

Third, missing ratings may affect comparisons because some movies may have been seen by more participants than others.

Finally, the dataset is intended for demonstrating SQL and R concepts rather than producing statistically representative estimates of movie quality.

15. Conclusion

This Assignment demonstrates a complete workflow from data collection to database storage and statistical analysis. The movie ratings were stored using a normalized relational database containing users, movies, and ratings tables. SQL joins were then used to retrieve an analysis-ready dataset, which was imported into R for data cleaning, missing-data handling, summary statistics, and visualization. The resulting user-item matrix also demonstrates how a simple movie rating dataset can serve as the foundation for recommender-system methods such as collaborative filtering.
